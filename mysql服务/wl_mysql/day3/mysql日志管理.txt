mysql 日志管理 
	事务日志
		顺序io--->随机io
			undo log 用于rollback
			redo log 用于commit
				wal： write ahead log
				innodb_log_file_size: 每个文件大小
				innodb_log_buffer_size: 指定缓冲大小 
				innodb_flush_log_at_trx_commit= 	
						0 由mysql的main_thread每秒将存储引擎log buffer中的redo日志写入到log file，并调用文件系统的sync操作，将日志刷新到磁盘
						1 每次事务提交时，将存储引擎log buffer中的redo日志写入到log file，并调用文件系统的sync操作，将日志刷新到磁盘。
						2 每次事务提交时，将存储引擎log buffer中的redo日志写入到log file，并由存储引擎的main_thread 每秒将日志刷新到磁盘。
	错误日志
			log_error： 定义错误日志路径 
			log_error_verbosity： 错误日志级别 1|2|3
								1：错误信息
								2：错误信息和警告信息
								3：错误信息，警告信息，一般信息（mysql运行相关信息）

    一般查询日志（一般处于关闭）
    	general_log： 一般查询日志 0 关闭 1 开启
    	general_log_file： 日志存放的位置	

    慢查日志：定位查询时间过长sql语句
    	slow_query_log： 慢查日志 开启 1 0 关闭 
    	slow_query_log_file： 慢查日志的位置 
    	long_query_time： 定义慢查日志时间 

  一般记录数据库数据变化日志，用来数据恢复
    二进制日志
    	binlog_format： statement |row|mixed
    	max_binlog_size: 设定二进制文件最大空间
    	sql_log_bin： 会话级开启或者关闭二进制日志
    	log_bin：开启二进制日志文件指定二进制日志文件位置 备注：需要指定server-id
    	expire_logs_days: 二进制日志文件最大存放时间
    	sync_binlog=[N]表示每写缓冲多次就同步到磁盘 0 根据系统机制同步
    二进制日志相关查询
    	SHOW {BINARY | MASTER} LOGS
    	SHOW MASTER STATUS
    	SHOW BINLOG EVENTS [IN 'log_name'] [FROM pos] [LIMIT [offset,] row_count]
    二进制命令客户端命令 
    	mysqlbinlog [OPTIONS] log_file --start-position=# 指定开始位置 --stop-position=# --start-datetime=#时间格式：YYYY-MM-DD hh:mm:ss --stop-datetime=
    清除日志	
    	PURGE { BINARY | MASTER } LOGS { TO 'log_name' | BEFORE datetime_expr }
		PURGE BINARY LOGS TO 'mysql-bin.000003'; #删除mariadb-bin.000003之前的日志
		PURGE BINARY LOGS BEFORE '2023-01-23';
		PURGE BINARY LOGS BEFORE '2023-03-22 09:25:30'; 
	重置日志 
		RESET MASTER 
	滚动日志 
		FLUSH LOGS

备份： 防止数据丢失（误操作）
逻辑备份 sql语句

物理备份 备份数据 

冷备份  不能读写

温备份  能读不能写 （myISAM）
 
热备份  能读写（innodb）

完全备份 全部备份

增量备份 备份增加的数据

mysqldump	支持逻辑备份  不支持增量备份   
		mysqldump  常见选项 
			--all-databases 备份所有的库
	 		--databases     指定库 
	 		--flush-logs    滚动二进制日志  
	 		--master-data   记录二进制日志位置  
	 						1： 不注释 
	 						2： 注释
	 		
	 		--lock-tables   锁表 

	 		--single-transaction innodb 启动大事务实现热备

备份： 
	mysqldump 完全备份 
		backname="file$(date +%F-%T)"
		mysqldump  --all-databases --flush-logs --master-data=2 --single-transaction > $backname.sql
	二进制文件
		mysqbinlog --start-position=	--stop-position=  > xxx.sql

还原  
	临时关闭二进制日志文件
		set sql_log_bin=0 
		source 完全备份的sql文件 
		source 二进制日志备份文件
	开启二进制日志文件
		set sql_log_bin=1 

perconna xtrabackup
	完全备份  
		xtrabackup --backup --target-dir 备份的路径 

	还原 
		xtrabackup --prepare  --target-dir 备份路径  

		xtrabackup --copy-back --target-dir 备份路径

	完全+增量
		完全
			xtrabackup --backup --target-dir 备份的路径  
	    第一次增量 
	    	xtrabackup --backup --target-dir  备份的路径   --incremental-basedir 完全备份路径
	    第二次增量
	    	xtrabackup --backup --target-dir  备份的路径   --incremental-basedir 第一次增量路径 
	 	还原准备
	 	  准备完全备份
	 		xtrabackup --prepare --apply-log-only  --target-dir 完全备份路径
	 	  准备第一次增量备份 
	 	  	xtrabackup --prepare --apply-log-only  --target-dir 完全备份路径  --incremental-dir 第一次增量备份  
	 	  准备第二次增量备份
	 	  	xtrabackup --prepare   --target-dir 完全备份路径  --incremental-dir 第二次增量备份 
	 	还原 
	 		xtrabackup --copy-back --target-dir 完全备份 
	 	可能需要二进制日志文件 
	 		mysqlbinlog
